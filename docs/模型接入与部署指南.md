# 坝上植物实习小助手：模型接入与部署指南

## 1. 迁移包说明

项目提供两个压缩包：

- **便携运行版**：包含已经构建好的 `dist`、启动脚本和使用文档。适合课堂展示与普通使用。
- **模型接入开发包**：包含 React 源码、290 条知识库记录、全部图片、导入脚本和已接入 BioCLIP-2 的 `model_service`。适合在另一台电脑继续开发。

便携版仍需要 Python 3 来启动本地静态服务器。浏览器不能直接双击 `index.html`，因为知识库通过 HTTP 读取 JSON。

## 2. 在 Windows 上直接运行便携版

1. 解压压缩包到路径较短的位置，例如 `D:\BashangPlantAgent`。
2. 安装 Python 3，并在安装程序中勾选 `Add Python to PATH`。
3. 双击 `启动便携版.bat`。
4. 浏览器访问 `http://127.0.0.1:4173/`。
5. 关闭命令行窗口即可停止服务。

端口被占用时，在命令行运行：

```powershell
python -m http.server 4174 --directory dist
```

然后访问 `http://127.0.0.1:4174/`。

## 3. 在开发包中启动前端

建议安装 Node.js 20 LTS 或更高版本。

```powershell
cd D:\BashangPlantAgent
npm install
npm run validate:data
npm test
npm run dev
```

开发地址为 `http://127.0.0.1:5173/`。修改代码后 Vite 会自动刷新。

生成生产版：

```powershell
npm run build
```

## 4. 前后端职责

前端负责：

- 展示 290 条植物记录和本地图片；
- 采集多张图片与器官标签；
- 调用模型服务并展示真实返回结果；
- 在浏览器 IndexedDB 中保存待复核记录。

模型服务负责：

- 加载 BioCLIP 权重；
- 完成图像编码、多器官融合和候选排序；
- 保存 API Key 等机密配置；
- 返回符合协议的候选、检测框与警告。

DeepSeek Key 不得写入 `.env.local` 或 React 源码。Vite 的 `VITE_*` 变量会进入浏览器构建结果，只能放服务地址，不能放密钥。

## 5. 启动 BioCLIP-2 模型服务

```powershell
cd model_service
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8011
```

检查服务：

```powershell
Invoke-RestMethod http://127.0.0.1:8011/health
```

加载完成后 `modelReady` 为 `true`。模型未就绪时图片接口返回 503，不会生成伪候选。当前本机模型的完整说明见 [BioCLIP 模型使用与配置教学](BioCLIP模型使用与配置教学.md)。

## 6. 配置前端服务地址

复制 `.env.example` 为 `.env.local`：

```powershell
Copy-Item .env.example .env.local
```

内容示例：

```dotenv
VITE_VISION_API_URL=http://127.0.0.1:8011/v1/identify
VITE_MODEL_HEALTH_URL=http://127.0.0.1:8011/health
VITE_MODEL_TIMEOUT_MS=180000
```

修改环境变量后必须重启 `npm run dev`。模型加载完成时，图片识别页会显示“BioCLIP 已就绪”，并启用“BioCLIP 识别”按钮。

## 7. 图片识别请求协议

前端以 `multipart/form-data` 发送：

- `images`：1 至 8 个图片文件；
- `manifest`：JSON 字符串，包含 `partLabels`、`client` 和 `schemaVersion`。

响应示例：

```json
{
  "requestId": "REQ-20260711-001",
  "candidates": [
    {
      "plantId": "HBFC-071",
      "chineseName": "金露梅",
      "scientificName": "Potentilla fruticosa",
      "score": 0.91,
      "evidence": ["黄色五瓣花", "羽状复叶"]
    }
  ],
  "detections": [
    { "imageIndex": 0, "bbox": [0.12, 0.08, 0.72, 0.84], "confidence": 0.95 }
  ],
  "warnings": []
}
```

`score` 使用 0 至 1。`plantId` 应优先使用知识库中的 `HBFC-xxx`，便于前端跳转详情。模型不得把低于阈值的结果包装成确定结论。

## 8. 在 backend.py 中接入模型

推荐流程：

1. 在 `ModelBackend.load()` 中加载一次权重，不要每次请求重新加载。
2. 将完整照片输入 BioCLIP 图像编码器；复杂背景下应补充主体清晰的器官特写。
3. 预先为 290 条植物生成文本或参考图向量，并缓存在内存或磁盘。
4. 将多图、多器官得分聚合。全株、花、叶的证据应分别保留。
5. 输出前若最高分过低或前两名过近，返回警告并要求教师复核。

建议先做 Top-1、Top-5、Top-10 准确率和混淆矩阵，不要只看训练集准确率。训练集、验证集和测试集应按原始植株或拍摄批次划分，避免同一植株的近似照片同时出现在训练集和测试集。

## 9. 局域网部署

模型电脑地址假设为 `192.168.1.50`：

```powershell
uvicorn app:app --host 0.0.0.0 --port 8011
```

前端电脑的 `.env.local`：

```dotenv
VITE_VISION_API_URL=http://192.168.1.50:8011/v1/identify
VITE_MODEL_HEALTH_URL=http://192.168.1.50:8011/health
```

同时把前端地址加入模型电脑的 CORS：

```powershell
$env:PLANT_APP_ORIGINS="http://127.0.0.1:5173,http://192.168.1.60:4173"
```

仅在可信局域网开放端口。需要公网访问时，应增加 HTTPS、身份验证、文件大小限制、日志脱敏和请求频率限制。

## 10. 常见故障

| 现象 | 检查方法 |
| --- | --- |
| 页面空白 | 不要双击 HTML；使用本地 HTTP 服务 |
| 知识库加载失败 | 检查 `dist/data/plants.json` 是否存在 |
| 没有模型按钮 | 检查 `.env.local`，重启 Vite |
| 浏览器提示 CORS | 将前端完整来源地址加入 `PLANT_APP_ORIGINS` |
| 服务返回 503 | `backend.ready` 仍为 `false`，模型尚未加载 |
| GPU 未使用 | 检查 PyTorch CUDA 版本、驱动和模型设备 |
| 图片保存失败 | 检查浏览器 IndexedDB 权限与磁盘空间 |

## 11. 发布前检查

```powershell
npm run validate:data
npm test
npm run build
```

还应在桌面和手机宽度检查四个模块，确认控制台无错误、图片无断裂、模型不可用时不显示虚假候选。
